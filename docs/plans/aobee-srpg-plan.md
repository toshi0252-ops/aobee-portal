## 1. 作品（仮題）

**シリーズ名『あおびー大戦』（仮）／ 第1話「止まった村を守れ！」**

タイトル候補（未決定・§11）:

| 候補 | 印象 |
|---|---|
| 『あおびー大戦』 | 一番シンプルでシリーズ化しやすい。本書の推し |
| 『あおびー戦記 〜止まった村の歯車〜』 | 物語寄り。大作RPGと世界観が地続きに見える |
| 『ほしと歯車の大戦線』 | 固有の世界観は出るが、あおびーの名前が入らない |

- ジャンル: ターン制シミュレーションRPG（スパロボ型）。ブラウザ、スマホ対応
- 試作は **1マップ完結・10〜15分**。面白ければ2面目以降と育成要素を足す
- 実在作品のキャラクター・機体・名称・楽曲は使わない。借りるのは「マップでユニットを動かし、戦闘予測を見て、反撃を選ぶ」という**システムの構造だけ**で、固有名詞はすべてあおびーオリジナルにする

## 2. SRCへのオマージュ（この企画の芯）

としが昔はまった SRC（Simulation RPG Construction）の面白さは、遊ぶことと作ることが地続きだった点にある。本作はそこを設計に取り込む。

1. **データ駆動**: ユニット／パイロット／武器／マップ／会話イベントを、コードから分けたデータファイル（JSON）で定義する。1面足すのにエンジン側を触らなくて済む形にする（§8に定義例）
2. **1話完結の積み重ね**: 長編を一気に作らず、SRCのシナリオ集みたいに「1話＝1マップ」で増やせる構造にする
3. **会話イベントが本体**: 出撃前会話、ボスとの掛け合い、クリア後会話まで含めて「スパロボらしさ」とする。戦闘だけのゲームにしない

## 3. デザインの柱

1. **予測画面で考える楽しさ** — 攻撃前に命中率・予想ダメージ・反撃の有無を見せ、武器と「反撃／防御／回避」を選ぶ。運任せにしない
2. **ほしコマンドで逆転できる** — 精神コマンド相当をあおびー風に改名した「ほしコマンド」（§6）。使うタイミングの判断が一番の駆け引き
3. **テンポ優先** — 戦闘演出は1回5秒以内、スキップ可。敵フェイズも倍速可。スマホでサクサク進む
4. **わるびーは毎話出るライバル** — 大作RPGと同じ方針。第1話は敵として登場し、ボスを操って撤退する
5. **初心者に分かりやすく** — 大作RPG試作でとしに「分かりやすいし初心者向け」と評価された方針を継承。移動範囲・攻撃範囲の色分け、目的の常時表示、敗北してもその場リトライ

## 4. 世界観と第1話のあらすじ

はぐるま村の秋祭り。目玉はガルド工房が作った祭り用からくり機体（作業機）のパレードだった。
ところが本番直前、村の大歯車の**制御歯車**をわるびーが持ち去り、制御を失ったからくり機体たちが暴走を始める。
あおびーたちは急遽、祭り用機体に乗って村を守ることに――「作業機やのに武器ついてるやん」「……仕様です」。

- 機体が「兵器ではなく作業機の転用」なので、あおびーの明るい世界観のまま戦える
- ボスのからくり人形は、大作RPG試作のボスをそのまま「暴走した主演機体」として再登場させる

## 6. システム（試作で入れる範囲）

### 基本フロー

味方フェイズ（全ユニットを好きな順に行動）→ 敵フェイズ → 次ターン。行動は「移動＋攻撃（または機能）」で1回。

1. ユニットをタップ → 移動範囲（青）と攻撃可能範囲（赤）を表示
2. 移動先をタップ → 武器を選ぶと**戦闘予測画面**（命中率／予想ダメージ／敵の反撃武器とその命中・ダメージ）
3. 敵の反撃方法（反撃／防御＝ダメージ半減／回避＝命中半減）を選ぶのは防御側。敵AI分は自動で最適を選ぶ
4. 戦闘演出（横向き対峙・カットイン風の拡大表示・ダメージ数字・HPバー）→ 経験値取得、撃墜で「歯車コイン」獲得（試作では記録表示のみ）

### 計算式（シンプル版）

- 最終命中率 = 武器命中補正 ＋ 自分の命中 − 相手の回避 − 地形回避補正（5〜100%で丸める）
- ダメージ = （武器威力 ＋ 自分の攻撃補正 − 相手の装甲）× 地形防御補正。防御選択時は半減
- 気力: 攻撃する／被弾する／撃墜で上昇。必殺武器と一部ほしコマンドの条件にする

### ほしコマンド（精神コマンド相当）

SP制。各パイロット2つまで（試作）。「必中」「ひらめき」「不屈」「根性」「応援」「激励」「加速」「集中」――効果はスパロボの定番を踏襲し、名前と演出をあおびー風にする。

### 地形

| 地形 | 効果 |
|---|---|
| 平地・道 | なし（道は移動コスト0.8相当で進みやすく） |
| 森 | 回避+15%、移動コスト2 |
| 村・建物マス | 回避+10%、自フェイズ開始時にHP10%回復（施設扱い） |
| 川 | 移動コスト3、防御補正なし |
| 歯車タワー周辺 | ボス布陣エリア。第1話では演出のみ |

### 第1話マップ

- **12×9マス**。スマホ縦画面で全体が見える大きさに収め、タイルは大きめにして誤タップを防ぐ（大作RPG試作で学んだ「スマホで切れる・隠れる」問題を最初から避ける）
- 配置: 南＝味方出撃位置（工房前）、中央＝村の広場（番人コグ）、北＝歯車タワー前（ボス）、東西に森と川を置いて進路を2つ作る
- 勝利条件: からくり人形の撃破 ／ 敗北条件: あおびーの撃墜（味方の全滅でも敗北）
- イベント: 開始時会話 ／ 3ターン目にサビつきコグ×2増援＋会話 ／ 番人コグHP半分で会話 ／ ボス接敵時と撃破時にわるびーの掛け合い ／ クリア後会話
- おまけ条件（熟練度相当）: **6ターン以内クリア**でクリア画面に「ほし勲章」を表示し、次話への引きセリフが変わる

### 試作で「入れない」と決めるもの

改造・強化、経験値による育成の引き継ぎ、MAP兵器、合体攻撃、分岐ルート、出撃ユニット選択、インターミッション画面（出撃前会話で代替）。どれも「2話以降を作ると決めてから」の要素で、試作の判定を重くしない。

## 8. データ駆動の設計（SRCらしさの実装面）

置き場所は将来ポータルに入れる形で `games/srpg/` を想定し、エンジンとデータを分ける。

```
games/srpg/
  index.html        … 画面とエンジン
  data/
    pilots.json     … パイロット（能力・ほしコマンド・セリフ顔）
    units.json      … 機体（HP・EN・移動・武器）
    stage1.json     … マップ配置・勝利条件・イベント列
```

定義イメージ（stage1.json のイベント1件）:

```json
{ "trigger": "boss_hp_below_50%",
  "talk": [ { "who": "warubee", "text": "ふ、ふっ…まだまだこれからだよ？" },
            { "who": "aobee", "text": "強がっても歯車は返してもらうで！" } ] }
```

この形なら、2話以降は「マップと会話を書く」作業が中心になり、としがSRCでシナリオを作る感覚で後から手を入れられる。

## 9. 操作（スマホ前提）

- 基本はタップのみ: ユニット選択→移動先→武器→予測確認→決定。仮想コントローラは使わない
- 戦闘演出はタップでスキップ、敵フェイズは倍速ボタン
- 誤タップ対策: 攻撃決定は予測画面で必ず1回確認を挟む。「行動終了」の取り消しは攻撃前まで可
- PCではマウス＋キーボード（Escでキャンセル等）も対応する

## 10. 判定ゲート（試作を作る場合）

試作1面の完成時に、としが以下5項目を判定する。3項目以上が好評価でなければ、2話以降に進まず作り直し又は中止。

1. マップで動かす気持ちよさ（移動→攻撃のテンポと範囲表示の分かりやすさ）
2. 戦闘予測と反撃選択の駆け引き（考えて選べたか）
3. 戦闘演出のワクワク感（カットイン風表示と必殺技）
4. 会話イベントのスパロボらしさ（出撃前・ボス掛け合い・クリア後）
5. **2面目を遊びたい／自分でも面を作ってみたいと思えたか**（SRC基準）

## 11. 未決定事項（としの判断待ち）

## 12. 制作ステップ（試作を作ると決めた場合）

4. プレビューで実プレイ確認（詰まり・表示切れ・スマホ操作）→ としが§10で判定
