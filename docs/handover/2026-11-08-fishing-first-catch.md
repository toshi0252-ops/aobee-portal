# 連携資料: フィッシング「はじめてサポート」（2026-11-08、Muse）

## 背景（遊戯監査 P1「序盤のヒット率・初回成功体験」）

監査の実プレイでは3キャストでヒット1回・釣果0、待ち時間の手応え不足が課題になった。本体コードの仕組みは模擬生態系型で、壊れているわけではない:

- 魚は個別エージェント（初期6匹、好奇心 curious 0.84〜1.05 の小物中心）。仕掛けの近く（距離18以内）を泳ぐ魚が確率で寄る（approach → inspect → nibble）
- nibble の最後に18%で「離れた」（spook）になり、82%で bite → ファイト開始
- ファイトは tension 100 で糸切れ、slack 100 で逃げられ、stamina 0 で釣獲。引いている最中に巻くと tension が急上昇し、初見は即死しやすい

問題は「最初の1匹までが遠い」こと。確率と腕前の壁が序盤に集中している。

## 制約と方式

- 本体 `games/aobee_pico_fishing_v68_dual_guide.html` は 7.2MB で、GitHub 連携の push が HTTP 413（容量超過）になり編集不可（検証済み。テスト用ブランチ test/push-capacity-20261108 に未加工コピーの push を試して失敗を確認。※このテストブランチは削除用ツールがなく残置されているので、気になれば GitHub の Web から削除してください）
- そのため既存の確立方式に倣い、**ラッパー側スクリプトからの注入**で実装した（fishing-idle-trial.js と同じ流儀、本体無改造）:
  - 新規 `assets/fishing-first-catch.js`（ラッパー側ローダー＋注入パッチ）
  - `games/aobee_pico_fishing_v68_portal.html` に `<script defer src="../assets/fishing-first-catch.js?v=1">` を1行追加
- 注入パッチは本体側の既存後付けレイヤー（Block 5 / FUN層）と同じく、ゲーム側グローバルの `updateFish` / `end` を包む。状態は本体の `catchCount`（釣獲数）を基準にし、**初キャッチ成立で全アシストが自動的に切れる**。

## アシスト内容（catchCount === 0 の間だけ）

1. **寄りの上乗せ**: 魚が仕掛けに寄る範囲を 18 → 26 に広げ、寄る確率も上乗せ（本体 curious*dt*0.9 に curious*dt*1.8 を加算相当）。
2. **7秒保証**: キャスト後7秒たってもどの魚も寄っていない場合、いちばん近い魚が必ず寄ってくる（死に待ちの解消）。
3. **spook 無効**: 最初の魚は nibble 後に「離れた」にならず、寄り直して必ず bite する。
4. **ファイト1回救済**: 最初のファイトで糸切れ/逃げられになっても1回だけ肩代わり（tension/slack を62に戻して継続、トースト表示）。2回目は通常どおり終了する。

## 対象外・不変

- 本体のバランス（魚の種類・curious・ファイト数値・FLOW等）は一切変更していない。アシストは初キャッチまでの時限措置。
- 対応導線はポータルのラッパー経由のみ（本体URLへの直アクセスでは従来動作）。これは idle ポーズ試作など既存のラッパー方式と同じ前提。
- 注入に失敗した場合（関数が見つからない等）は約10秒で諦めて無介入。ゲーム本体の動作には影響しない設計。

## 検証

- ローダーと注入パッチは構文検証済み。注入パッチのロジックはスタブ環境で単体テスト済み（7秒保証で最寄りの魚だけが approach へ、spook 反転、ファイト救済は1回だけ、釣獲後は無効 — 全件パス）。
- プレビュー（raw.githack 経由のラッパー）で実プレイ確認: 初キャストから bite までの時間、悪い巻き方での救済発動と2回目の通常終了、通常プレイの無事を確認する（結果は PR に追記）。
