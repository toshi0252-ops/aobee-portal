- 2026-11-06 Muse 検証: 釣り本体の実コードで差し替え可否を確認。setAobee(k) は通常 script 内のトップレベル関数でラッパーから捕捉可能、idle/cast は AOBEE_RODLESS へ差し替える実装、竿は handAnchor 要素基準で別描画のためスプライト差し替えでは竿位置は動かない。差し替えは idle のみ・事前ロード成功時のみ有効化・失敗時は無介入でフォールバック、という方式案を PR に提示済み。残る未確定は handAnchor と正面ポーズの手位置の視覚的整合（実機確認が必要）。残判断は とし の試作実施判断のみ。
- 2026-11-07 Muse 検証結果（PR #11 コメント 6696813940 に詳細）: 試作 PR #12 を実施したが、葵の受入条件3（竿の接続）は不成立。確認済み事実: (1) プレビュー環境（githack）の2回のブラウザ確認＋とし本人のスマホ実機確認のいずれでも、プレイ画面のキャラは従来デザインのままで差し替えは描画に反映されず。(2) 竿は handAnchor（隠れた DOM キャラ）基準の別描画でスプライトと構造的に独立しており、公式正面ポーズの前足位置とは合わない — とし本人からも「竿は独立して動いてる」との所見。(3) フォールバック（素材が読めない場合は無介入で従来表示）は設計どおり機能。未切り分け: プレビューで発動しなかった原因が配信側の atlas 読込失敗（curl で 403 観測）かフック側かはコンソールなしでは判定できず、本番 Pages で発動するかはマージしないと分からない。Muse の見解は条件5どおり見送り＋別案（竿なし待機ポーズ／手位置が合う専用ポーズ）。最終判断は とし。
